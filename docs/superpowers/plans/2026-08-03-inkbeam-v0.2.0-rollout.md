# Inkbeam v0.2.0 Staged Rollout Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Rename the public repository and release Inkbeam through real RC1, RC2, and final installations, proving Developer ID trust, Chrome/native capture, consent-first signed updates, modified-document safety, public-byte integrity, and stable-feed rollback before calling v0.2.0 complete.

**Architecture:** Integrate the three implementation plans on the renamed public repository, then run the local release CLI as a guarded stage machine. Publish every candidate as a GitHub Pre-release first, verify the public bytes, publish a signed beta feed, and gather environment-specific runtime evidence. Promote the exact final candidate only after RC2-to-final update proof; if stable-feed publication or verification fails, restore the previous feed and immediately demote the same GitHub release.

**Tech Stack:** Git, GitHub CLI, GitHub Actions validation, Developer ID, Sparkle 2.9.4, macOS 26.5.2, macOS 15.x, Rosetta 2, Chrome stable, Screen Recording TCC, Markdown evidence, Git notes

## Global Constraints

- Execute only after the clean-cut, Sparkle updater, and direct-release pipeline plans are implemented, reviewed, committed, and green.
- This plan performs external mutations: repository rename, branch/PR integration, tags, public releases/assets, GitHub Pages feeds, Git notes, and final README. Before each mutation, run and record the preceding read-only assertion.
- The source of truth is `docs/superpowers/specs/2026-08-03-inkbeam-v0.2.0-official-release-design.md`; the stable CLI contract is defined in the direct-release pipeline plan.
- No stage begins from a dirty worktree, unverified SHA, failed CI run, missing exact credential, incomplete previous gate, or skipped release-critical test.
- Current evidence shows zero valid code-signing identities. Task 1 remains blocked until the operator installs the exact Developer ID Application certificate/private key and the real preflight passes. An Apple Developer membership alone is insufficient.
- Never mark an operator check PASS from unit tests, shell output alone, prior runs, or visual assumptions. Record actual machine, OS, architecture, Chrome version/profile, artifact SHA, and observation.
- The release Mac is macOS 26.5.2 on Apple Silicon. Required additional evidence is clean macOS 15.x, Rosetta x86_64, fresh Chrome stable profiles, reset Screen Recording TCC, and isolated updater consent profiles.
- RCs and the final candidate stay `draft=false`, `prerelease=true`, `make_latest=false` until their exact gates pass. Do not silently replace a tag or public asset.
- The beta feed may reference verified public Pre-releases. The stable feed may reference only a verified public non-prerelease release.
- If a public RC later fails a release-critical gate, immediately prepare a newly signed beta feed without that RC, run `Scripts/release/inkbeam-release withdraw-candidate TAG`, verify the public beta bytes, and stop until a replacement RC is ready.
- Modified-document update proof uses two isolated RC1 installations or restorable snapshots: one for cancel then save/retry, another for explicit discard. Do not reuse a contaminated state.
- A release blocker stops the rollout. Cosmetic copy issues may be recorded; trust, install, privacy, data safety, update, native capture, or Chrome capture defects may not ship.
- Commit acceptance documents after each stage. Push `refs/notes/inkbeam-acceptance` only after its referenced evidence validates.
