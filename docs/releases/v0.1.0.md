# MyShottr v0.1.0

The first public MyShottr release adds local macOS region capture, clean Chrome
visible-viewport capture, editable Quick Ink annotations, composited PNG
output, and `.myshottr` project files.

## Downloads

- `MyShottr-0.1.0-macos.zip` — macOS 15+ app; unsigned and unnotarized
- `MyShottr-Chrome-0.1.0.zip` — unpacked Chrome extension for Developer mode
- `SHA256SUMS.txt` — SHA-256 checksums for both archives

## Important installation note

Move MyShottr to `/Applications`, then use Finder's Control-click **Open**
flow. If macOS still blocks the app, use **System Settings → Privacy &
Security → Open Anyway**. Open the app once before loading the Chrome
extension so the per-user Native Messaging Host is registered.

This distribution is unsigned and unnotarized. The two executables may contain
link-time ad-hoc signatures created by the build; they have no Developer ID
identity and the release has not been reviewed or notarized by Apple. The
Chrome package is an unpacked extension, not a Chrome Web Store package.

## Verification status

The release workflow publishes only when the tag commit, checked-out commit,
remote `main`, workflow SHA, and a strictly validated `myshottr-acceptance` Git
note all identify the same commit.

`docs/images/editor-quick-ink.png` is the reviewed `selected Rectangle` state
copied from the deterministic browser fixture used by the Darwin visual suite,

`a1c1a69b943ce42a4008cc41e8a930a5bb383445`. The fixture composes the

units around closed test inputs. It sends the production bridge a validated
`loadDocument` message, then renders a neutral generated source PNG with a real
selected Rectangle, Context Rail, and Fit Image / Fit Selection controls. No

This image demonstrates the current Quick Ink editor shell and interaction
layout. The fixture owns only its closed inputs and native transport boundary;
it is not the full production `App`, a native NSWindow, or ScreenCaptureKit
acceptance proof, and it does not substitute for the interactive acceptance
note required by the release workflow.

## Known limitations

- Chrome captures only the visible viewport; full-page capture is not included.
- The extension requires Developer mode and manual **Load unpacked**
  installation.
- Desktop mockups and other presentation frames are not included.
- Unsaved documents are not restored after the app terminates unexpectedly;
  save an editable `.myshottr` project to keep ongoing work.
- Safari, Firefox, OCR, capture history, and automatic updates are not included.
- Developer ID signing, Apple notarization, the Mac App Store, and the Chrome
  Web Store are not included.
